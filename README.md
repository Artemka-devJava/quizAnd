# Quiz Multiplayer - Android версия

Многопользовательское квиз-приложение для Android, похожее на iOS версию из репозитория [quizIOS2](https://github.com/Artemka-devJava/quizIOS2.git).

## Особенности

- 🎮 **Две роли**: Ведущий (Host) и Игрок (Player)
- 🔗 **Локальная сеть**: Подключение через TCP сокеты
- ⚡ **Система Buzz**: Игроки нажимают кнопку для ответа, ведущий выбирает ответчика
- 📊 **Скорборд**: Отслеживание очков игроков
- 📱 **Jetpack Compose**: Современный UI фреймворк
- 🔄 **Real-time коммуникация**: WebSocket-подобный протокол (newline-delimited JSON)

## Архитектура

### Модели (`models/GameModels.kt`)
- `UserRole`: ХОСТ или ИГРОК
- `AppPhase`: Фазы приложения (splash, role selection, lobby, game, etc.)
- `GameMessage`: Структура сообщения между хостом и игроками
- `PlayerInfo`: Информация об игроке
- `QuestionPayload`: Структура вопроса
- `AnswerPayload`: Ответ игрока
- `AnswerResultPayload`: Результат ответа

### Сетевой уровень (`network/NetworkManager.kt`)
- **TCP соединение**: Использует `Socket` API для прямого подключения
- **Сканирование сети**: Автоматический поиск ведущего в локальной сети
- **Newline-delimited JSON**: Протокол обмена сообщениями
- **Асинхронная обработка**: На базе Kotlin корутин

### ViewModel (`viewmodels/AppViewModel.kt`)
- Управление состоянием приложения
- Обработка сетевых событий
- Логика игровых раундов и подсчета очков

### UI Слой (`ui/screens/GameScreens.kt`)
- **SplashScreen**: Экран загрузки
- **RoleSelectionScreen**: Выбор роли (Хост/Игрок)
- **HostLobbyScreen**: Лобби хоста с ожиданием игроков
- **HostControlScreen**: Управление игрой (раунды, оценка ответов)
- **PlayerJoinScreen**: Присоединение к серверу
- **PlayerWaitingScreen**: Ожидание начала игры
- **PlayerQuestionScreen**: Игровой экран с кнопкой Buzz

## Сетевой протокол

### Сообщения (MessageKind)
- `HELLO`: Подтверждение присоединения игрока
- `PLAYER_LIST`: Список подключенных игроков
- `GAME_STARTED`: Начало игры
- `ROUND_OPENED`: Раунд открыт, ожидаем ответы
- `BUZZ`: Игрок нажал кнопку ответа
- `RESPONDER_SELECTED`: Выбран ответчик
- `RESPONDER_CLEARED`: Ответчик отклонен (неверный ответ)
- `ROUND_CLOSED`: Раунд закрыт
- `ANSWER_RESULT`: Результат ответа (верно/неверно)
- `ERROR`: Ошибка

### Формат
```json
{
  "id": "uuid",
  "kind": "GAME_STARTED",
  "senderID": "uuid",
  "senderNickname": "Ведущий",
  "player": { "id": "uuid", "nickname": "Игрок1" },
  "players": [...],
  "question": {...},
  "answer": {...},
  "answerResult": {...},
  "scoreValue": 1,
  "text": "Описание",
  "sentAt": 1234567890
}
```

## Использование

### 1. Запуск Хоста
- Выберите роль "Ведущий"
- Введите ник и порт (по умолчанию 5000)
- Нажмите "Запустить сервер"
- Сервер будет ожидать подключения игроков

### 2. Присоединение Игрока
- Выберите роль "Игрок"
- Введите свой ник
- Выберите сервер из списка
- Нажмите "Подключиться"
- Ожидайте начала игры

### 3. Игровой процесс
- Хост открывает раунд ("Открыть раунд")
- Игроки нажимают "BUZZ!" для ответа
- Хост выбирает ответчика и оценивает ответ
- Правильные ответы начисляют очки
- Хост закрывает раунд и переходит к следующему

## Разрешения

Приложению требуются следующие разрешения:
- `INTERNET`: Для сетевых соединений
- `ACCESS_NETWORK_STATE`: Для проверки подключения к сети
- `CHANGE_NETWORK_STATE`: Для работы с сетевыми соединениями

## Особенности реализации

1. **Автоматический поиск**: Сканирует локальную подсеть для поиска доступных хостов
2. **Переподключение**: Автоматически пытается переподключиться при разрыве соединения
3. **Real-time обновления**: Использует Kotlin Flow для реактивного обновления UI
4. **Многопользовательский Buzz**: Только один игрок может быть текущим ответчиком в раунде
